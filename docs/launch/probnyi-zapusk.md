Дата: 29.10.2026 · Проверял: Claude по запросу Николая · Сборка: `bash tools/deploy/build_dist.sh`, 2049 файлов, 656 МБ.

## Как проверяли и чем это отличается от хостинга

Docker и Apache в нашем облаке недоступны: образ `php:8.3-apache` не скачивается, пакет `apache2` не ставится. Поэтому сайт поднят так:
- **PHP 8.3 настоящий:** `site/api/lead.php` работает как есть, через встроенный сервер PHP;
- **Apache эмулирован** небольшой программой. Она читает `dist/.htaccess` и выполняет его правила: `RewriteRule`/`RewriteCond` (HTTPS, без www, 100 старых адресов, `/api/*`), `RedirectMatch 404`, `FilesMatch … Require all denied`, `DirectoryIndex`, `ErrorDocument 404`, `Header always set`, `Cache-Control`, сжатие `DEFLATE`;
- **почта перехвачена:** `sendmail_path` PHP пишет письма в файл. Настройки ТЕСТОВЫЕ: в `private/ds-config.php` уровнем выше папки сайта, как на хостинге, без токенов мессенджеров;
- **браузер:** Playwright (Chromium), ширина 1440 (ПК) и 390 (телефон).

Что эмуляция не покажет и что нужно повторить на хостинге в день переезда (`docs/launch/pereezd.md`, раздел 3):
- версия Apache и включённые модули у RU-CENTER;
- права на папку `private/`;
- работа `mail()` на хостинге: доходят ли письма и не попадают ли в спам (SPF, DKIM, DMARC);
- отправка в MAX или Telegram с настоящим токеном.

## Что исправлено (PR #28, ветка `kolya/probnyi-zapusk`)

1. **Сервисный бот отправлял заявки только письмом.**
   - Было: в `warranty.html` настройка `window.DS_SERVICE = { endpoint: "" }` перекрывала адрес `/api/service`. Бот сразу предлагал «Отправить письмом», и заявка на сервер не попадала.
   - Стало: адрес берётся из `service-bot.js` (`/api/service`), письмо осталось запасным вариантом, если сервер не ответил.
2. **Письмо по сервисному обращению.**
   - Было: серия оборудования подписана «Послушать» (подпись из формы шоу-рума), гарантия приходит кодом `warranty`/`post`.
   - Стало: «Серия: TAURA», «Гарантия: да, на гарантии (до 3 лет)».
3. **Страница 404 на вложенных адресах.**
   - Было: ссылки на ней относительные (`./mnav.css`), поэтому на адресе вроде `/catalog/net-takoy/` стили и картинки не грузились.
   - Стало: `build_dist.sh` добавляет в `dist/404.html` строку `<base href="/">`, только для хостинга (превью на GitHub Pages живёт не в корне). Проверено: 0 битых ссылок.
4. **Карта сайта без английской версии.**
   - Было: в `sitemap.xml` были только 184 русские страницы.
   - Стало: 366, добавлены 182 английские. Их добавляет `tools/seo/build_seo.py`: это страницы из `site/en/`, у которых canonical ведёт на них самих.
5. **Canonical у белых вариантов PILLAR в английской версии.**
   - Было: `en/p-pillar-a-wh.html` и `en/p-pillar-p-wh.html` указывали canonical на русскую страницу.
   - Стало: на английскую (`tools/i18n/build_en.py`).
6. **Мелочи:** в `README.md` домен `nikolaymilkov.com` заменён на `ds-proaudio.ru` (решение Р1); папка `private/` и `ds-config.php` добавлены в `.gitignore`.

## Замечания без правок (на решение Тимура)

- **Главная по двум адресам.**
  - `index.html` и `Main.dc.html` — одна и та же страница; canonical у обеих указывает на `/`, поэтому для поиска это не дубль.
  - Правило `Main.dc.html → /` в `.htaccess` закомментировано. Его можно включить, но тогда каждый переход «на главную» со 189 страниц будет делать лишний шаг 301.
  - Лучше сначала заменить ссылки `./Main.dc.html` на `./` и только потом включать правило.
- **Кэш картинок «на год, без перепроверки»** (`immutable`). Если заменить фото на файл с тем же именем (например, `metp-1.jpg`), вернувшиеся посетители увидят старое фото до года. Новое фото лучше класть под новым именем, или нужно уменьшить срок кэша.
- **Общий лимит 60 заявок в час на весь сайт** защищает почту от спама. Но если бот наберёт 60 заявок за час, живые посетители до конца часа увидят предложение отправить письмо. Сами заявки не потеряются.
- **В виджетах objform, footbot и service-bot нет поля-ловушки.** Они отправляют JSON из скрипта, а сервер принимает только JSON (415 на обычную отправку формы), поэтому простые спам-боты их не достанут. Если спам пойдёт, можно добавить капчу Yandex SmartCaptcha.
- **`SHA256SUMS` открыт для чтения.** Секретов в нём нет, только список файлов сайта. После сверки в день переезда его можно удалить с хостинга.

## Как повторить

```
bash tools/deploy/build_dist.sh
# дальше — на компьютере с Docker (так проверка ближе всего к хостингу):
docker run --rm -p 8080:80 -v "$PWD/dist":/var/www/html -v "$PWD/private":/var/www/private php:8.3-apache \
  bash -c "a2enmod rewrite headers deflate && sed -i 's/AllowOverride None/AllowOverride All/' /etc/apache2/apache2.conf && apache2-foreground"
```
`private/ds-config.php` с тестовыми настройками положить в `private/` рядом с `dist/`: в образе это папка `/var/www/private`, уровнем выше корня сайта. Папка `private/` добавлена в `.gitignore`, чтобы файл с настройками случайно не попал в репозиторий.
