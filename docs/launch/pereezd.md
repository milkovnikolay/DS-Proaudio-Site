# Переезд сайта на ds-proaudio.ru — памятка на день запуска

Для кого: системный администратор компании (Александр Баринов).
Что делаем: на хостинге RU-CENTER сейчас работает старый сайт на Битриксе. Ставим на его место новый сайт из этого репозитория так, чтобы:
- старые адреса не потерялись (100 переадресаций 301 уже лежат в `.htaccess`);
- документы из папки `/upload/` старого сайта продолжали открываться;
- при любой беде старый сайт можно было вернуть за 15 минут.

Как читать: идите сверху вниз и ставьте галочку `[x]` у каждого сделанного шага. У каждого шага указано, **кто** делает и **как понять, что готово**.
Пароли в этот файл не пишем. Кто к чему имеет доступ, записано в таблице доступов по шаблону `docs/launch/dostupy-shablon.md`. Заполненную таблицу в репозиторий не кладём.

## 2. День переезда

Лучше начинать утром, когда на сайте меньше всего посетителей. На всё уходит 1–2 часа.

### 2.1. Подготовка отката (это и есть «вернуть за 15 минут»)
- [ ] **А.** В папке сайта на хостинге **сохранить копии файлов старого сайта, которые новый перезапишет:** `.htaccess`, `robots.txt`, `sitemap.xml`, `favicon.ico`, `404.html` (если есть). Положить их в `backup-<дата>/` уровнем выше папки сайта.
  *Готово:* в `backup-<дата>/` лежат эти файлы.
- [ ] **А.** Выписать файлы и папки, которые есть и в `dist/`, и на хостинге. Сравнить список файлов `dist/` со списком корня хостинга; совпадения тоже сохранить в `backup-<дата>/`.
  *Готово:* список совпадений записан в журнал.

### 2.2. Выгрузка
- [ ] **А.** Загрузить **содержимое** `dist/` в корень папки сайта, поверх старых файлов. **Ничего не удалять:** папка `/upload/` старого сайта остаётся на месте, на неё ведут ссылки на документы (PDF, GLL, DWG, ПО). Файлы Битрикса (`index.php`, `/bitrix/`) тоже пока не трогать: они нужны для отката.
  *Готово:* в корне хостинга есть `index.html` и `api/lead.php`, папка `/upload/` на месте.
- [ ] **А.** Положить `ds-config.php` в папку `private/` **уровнем выше** папки сайта и выставить права: на папку `700`, на файл `600`.
  *Готово:* адрес `https://ds-proaudio.ru/../private/ds-config.php` не открывается, а файл есть в SFTP.
- [ ] **А.** Сверить файлы по `SHA256SUMS`. По SSH:
  ```
  cd <папка сайта> && sha256sum -c --quiet SHA256SUMS && echo ВСЁ СОВПАЛО
  ```
  Если SSH нет, скачать 5–10 крупных файлов обратно (видео, `assets/3d/taura8.dat`) и сравнить суммы у себя.
  *Готово:* «ВСЁ СОВПАЛО» или совпали суммы выборочных файлов.

### 2.3. HTTPS
- [ ] **А.** В панели RU-CENTER проверить, что для `ds-proaudio.ru` и `www.ds-proaudio.ru` выпущен и включён сертификат (Let's Encrypt или платный) и он действует не меньше 30 дней.
  *Готово:* `https://ds-proaudio.ru` открывается с замком, без предупреждений.
- [ ] **А.** Проверить переадресации на HTTPS и без `www` (правила уже в `.htaccess`):
  ```
  curl -sI http://ds-proaudio.ru/       → 301, Location: https://ds-proaudio.ru/
  curl -sI https://www.ds-proaudio.ru/  → 301, Location: https://ds-proaudio.ru/
  ```
  *Готово:* оба запроса отдают 301 на `https://ds-proaudio.ru/`.

### 2.4. Почта: SPF, DKIM, DMARC
Без этих записей письма с заявками от `no-reply@ds-proaudio.ru` попадают в спам.
- [ ] **А.** SPF: в DNS есть одна TXT-запись `v=spf1 …`, в которой разрешён почтовый сервер хостинга RU-CENTER (точную строку дают в справке или поддержке RU-CENTER), например `v=spf1 include:<сервер хостинга> ~all`.
  *Готово:* проверка на mxtoolbox.com/spf.aspx без ошибок.
- [ ] **А.** DKIM: в панели почты RU-CENTER включить подпись DKIM для домена и добавить выданную TXT-запись.
  *Готово:* у тестового письма в Gmail («Показать оригинал») стоит `DKIM: PASS`.
- [ ] **А.** DMARC: TXT-запись `_dmarc.ds-proaudio.ru` со значением `v=DMARC1; p=none; rua=mailto:<ящик для отчётов>`. Через месяц, если отчёты чистые, перейти на `p=quarantine`.
  *Готово:* проверка на mxtoolbox.com/dmarc.aspx без ошибок.

## 4. Откат на старый сайт (15 минут)

Когда откатываться: главная или каталог не открываются, заявки не доходят и это не чинится за час, или сломан HTTPS.
- [ ] **А.** Вернуть старый `.htaccess` из `backup-<дата>/` в корень сайта.
- [ ] **А.** Переименовать новый `index.html` в `index.new.html`: Битрикс снова откроется через свой `index.php`.
- [ ] **А.** Вернуть из `backup-<дата>/` остальные сохранённые файлы старого сайта: `robots.txt`, `sitemap.xml`, `favicon.ico`.
- [ ] **А.** Открыть `https://ds-proaudio.ru/` и `https://ds-proaudio.ru/catalog/` в окне инкогнито: должен быть старый сайт.
- [ ] **А.** Если старый сайт открывается с ошибкой базы данных, восстановить базу из выгрузки (`mysql … < backup.sql`) и файлы из архива.
- [ ] **Т.** Записать в журнал, что пошло не так, и назначить новую дату.

*Готово:* старый сайт открывается и принимает заявки, как раньше.
